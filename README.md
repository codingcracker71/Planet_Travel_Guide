# Planet Travel Guide

## Project Option
Website

## Project Description
  This project will be a space travel guide website for different planets. It is made for space enthusiasts who want to further understand specific planets before they travel to them. What makes this experience interesting is how users can access detailed information for each planet. For instance, users can click on profiles for each planet and click to hide or unhide information regarding activities, general information, lodging options, and reviews of the planets from former tourists. The HTML of the page will include content such as planet names, planet images, planet information, navigation headings, a website title, and footer information. The CSS will organize this information into a navbar, header, content section, and footer. It will also organize the image buttons into a flex box and design the text and background colors. The JavaScript is applied to two buttons on the "About Us" and "Home" pages. Specifically, there is a JavaScript button on the "Home" page that shows an error message. Additionally, the JavaScript button on the "About Us" page shows different contact information options.

## Theme Interpretation
  This project is an interpretation of space tourism. Every day, scientists discover new planets and find ways to colonize them for human life, so the idea to send people to these planets is a topic of discussion. On Earth, tourists always plan to learn information about places they intend to travel to; therefore, this website operates with the idea that humans are able to visit and tour other planets.

## JavaScript Features
  Two of the JavaScript features are buttons. The button on the "Home" page says, "More Planets..." and it creates an error message that reads "Sorry, we're still finding more safe planets! Come back when our page is updated!" The purpose of this is to inform users that some content may not be ready yet, instead of leaving a button with no feedback to the prompt. The alternative to having more planet options is not having any readily available, and users deserve to know that information if the options do not show up. The second button is on the "About Us" page; it toggles between different contact information for users. This feature shares contact information while allowing users to contact the company with their preferred method.

## Responsive Design
The website is responsive on mobile devices with flex and CSS media queries. When the page shrinks, the header and text shrink, the image buttons stack vertically on each other, and the images on the planet pages stack above the dropdowns.

## User Testing
  The tester understood how to utilize the buttons for the planets, specifically the button for Mars. They also reported that the hovering mechanic worked well since there was a white border around the photo that appeared on the hover. Withal, the user noticed the title first, then the images, so the visual hierarchy is effective. Nevertheless, the confusion stemmed from convenience, responsiveness, and the purpose of the site. Specifically, they found that when they clicked the tabs on the navigation bar, a new tab in the browser opened up; they wanted the original page to change instead of having a new tab open. Additionally, they noted that there was no effect to the page after resizing the screen. Furthermore, the user mentioned that the purpose was unclear until they navigated to the “About Us” page, and they suggested adding a bit of information on the "Home” page to highlight what users can expect. Other than these errors, no unexpected user behavior was noted. 

## Revisions
  I changed the name of the website to create a clearer purpose for the website. I also changed the button image and planet page image sizes for the responsive design since the sizes originally did not change. The last two things I changed were the original JavaScript functions. Originally, I planned to make collapsibles for the planet page content and a mobile menu with JavaScript. However, the features would not respond when prompted. Instead, I made the buttons for the "About Us" and "Home" pages since they involved less complex code and quicker feedback.
